LingTest CLI

从 OpenAPI 到可审阅测试用例、自动执行和标准报告的本地优先 API 测试工具。

1. 产品定位

LingTest CLI 是一个开源、可脚本化、本地优先的 API 测试工具。它把 OpenAPI 文档转换为普通 JSON 测试用例，让用户先审阅和修改，再对真实服务执行，并输出适合开发者和 CI 平台消费的报告。

核心原则：确定性能力不依赖 AI；生成结果可审阅；密钥不写入用例；命令退出码可用于流水线门禁；Python SDK 与 CLI 共用同一套核心逻辑。

OpenAPI → 生成用例 → 人工审阅 → 执行 HTTP 请求 → JSON / JUnit 报告

非目标

0.x 阶段不替代完整的 API 管理平台，不提供 Web 协作后台，不承担生产流量压测，也不默认把接口文档或测试数据发送给第三方模型。

2. 目标用户与场景

后端开发者

从团队已有的 OpenAPI 快速得到 smoke tests，在本地修改后反复运行。

测试工程师

用结构化 JSON 管理接口用例，统一输出结果，并逐步接入 AI 辅助扩展边界场景。

DevOps / CI 维护者

在 GitHub Actions、Jenkins 或 GitLab CI 中执行接口门禁并收集 JUnit 报告。

Python 工具开发者

通过公开 SDK 函数组合用例生成与执行能力，构建内部质量工具。

3. 已实现功能

已实现

OpenAPI 3.x 读取

支持 YAML 和 JSON 文件，遍历 paths 和常见 HTTP 方法；缺少 paths 时给出明确错误。

已实现

确定性用例生成

根据 operationId、summary、参数、请求体和响应码生成用例，不需要模型 API key。

已实现

示例值推导

依次使用 example、default、enum 和类型默认值，支持 object、array、string、number、integer、boolean。

已实现

路径、查询与 Header 参数

填充路径占位符，构建 query 参数和规范中声明的 header；运行时可追加认证 Header。

已实现

HTTP 执行器

基于 HTTPX 顺序执行用例，支持 base URL、超时和运行时 Header，记录耗时与实际状态码。

已实现

可编辑中间格式

生成普通 JSON 用例文件。用户可在执行前审阅 expected_status、请求参数、body 和标题。

已实现

双格式报告

默认输出结构化 JSON；可选输出 JUnit XML，便于 CI 测试报告面板解析。

已实现

CI 退出码

全部通过返回 0，存在失败返回 1，输入或命令错误返回 2。

已实现

Python SDK 基础接口

公开 TestCase、TestResult、RunReport、generate_cases 和 run_cases。

已实现

工程化发行

采用 src layout、Hatchling、UV lock、PyPI 元数据、MIT License、pytest、Ruff 与 Twine 校验。

4. 用户工作流与命令

安装和生成

pipx install lingtest-cli
lingtest generate openapi.yaml -o cases.json

审阅和执行

lingtest run cases.json \
  --base-url https://api.example.com \
  -H "Authorization:Bearer $API_TOKEN" \
  --junit junit.xml \
  -o report.json

生成用例的数据契约

字段用途示例
id稳定用例标识get_user
method / pathHTTP 请求目标GET /users/42
expected_status成功判定标准200
headers / query规范推导的请求参数{"verbose": true}
body可选 JSON 请求体{"name": "test"}

5. 技术架构

模块职责
cli.pyTyper 命令、参数校验、输出和退出码。
openapi.py加载规范并生成确定性测试用例。
models.pyPydantic 公共数据模型。
runner.pyHTTPX 同步执行器和结果聚合。
io.pyJSON 用例、JSON 报告和 JUnit XML 序列化。

核心模块不依赖 FastAPI、Redis、Dramatiq 或数据库。未来模型 Provider、插件和并发执行器必须保持可选，避免破坏本地优先的基础安装体验。

6. 计划实现

0.2

OpenAPI 引用解析

支持本地和文档内 $ref、组合 schema、nullable、format 及更完整的 requestBody content。

0.2

配置文件与环境

增加 lingtest.toml、dev/staging 环境、变量替换、敏感值环境变量映射。

0.2

用例过滤

按 tag、operationId、路径、方法过滤；支持 include/exclude 和失败重跑。

0.2

更多断言

状态码之外增加 JSON path、schema、响应头、响应时间和包含关系断言。

0.3

认证策略

支持 OpenAPI securitySchemes、Bearer、API Key、Basic 和可插拔 token 获取。

0.3

并发与重试

提供可控并发、退避重试、速率限制；默认仍保持可预测的顺序执行。

0.3

HTML 报告

提供无需服务端即可打开的静态报告，包含摘要、耗时、失败详情和请求信息脱敏。

0.4

可选 AI Provider

从需求文本补充边界和异常用例、分析失败原因；支持 OpenAI-compatible Provider，明确展示数据发送边界。

0.4

pytest 导出

把审核后的用例导出为可维护 pytest 脚本，支持团队纳入现有测试目录。

1.0

稳定 SDK 与插件协议

承诺语义化版本兼容范围，为输入解析器、断言、认证和报告定义稳定扩展点。

优先级原则

先提高规范兼容性和确定性断言，再增加并发、报告和 AI。AI 能力作为可选增强，不能成为安装、生成或基础执行的必需条件。

7. 质量、安全与发布标准

  • 支持 Python 3.11 和 3.12；Windows、Linux、macOS 进入 CI 矩阵。
  • 每个命令覆盖成功、测试失败和输入错误三类行为；公共模型保持向后兼容。
  • 报告默认不保存运行时认证 Header；后续响应内容记录必须提供脱敏策略。
  • 每次发布运行 pytest、Ruff、构建和 Twine 检查，并使用 Git tag 与 PyPI 版本一致。
  • 遵循语义化版本；0.x 允许快速迭代，但破坏性变更必须记录在 changelog。
